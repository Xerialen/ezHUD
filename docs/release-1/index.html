ezHUD Release 1 — “Trust the geometry”

Epic #39, subissues #40–#43. Built by Sol (GPT-5.6-sol), specified and reviewed by Claude (Fable 5), 2026-08-04. Release commit: df07436 on main (merged PRs #44, #45, #46, #47, #48).

Scope

Release 1 makes the geometric measurements the editor and its QA depend on honest, and ships the first piece of demo control built on them:

  • #40 — the game view follows your window. Resizing the browser window now resizes the engine canvas and everything the engine reports about its screen. Before, the canvas froze at its boot size forever.
  • #41 — the engine tells the whole truth about resolution. The FTE state export now includes physical (the real backing-store pixels) next to the virtual console size, from one torn-read-safe snapshot.
  • #42 — QA judges content-sized elements fairly. The ping readout's width tracks its text; the matrix now judges it on position only, through a reviewed, exported exemption list.
  • #43 — demo pause, end to end. A Pause/Resume button in the demo bar that reflects the engine's own state — pausing from the console flips the button too, and a backend that can't pause says so instead of pretending.
  • Foundation (#44) — session/engine logging (F9 debug panel, GET /log, request-id correlation) and the 12-cell golden QA matrix that every claim below is measured with.

#41 — physical in the state export

Before: the QA assertion failed with source /state.physical must be an array, got undefined (RED log, red-41-physical/). After: physical is an integer pair equal to the canvas backing store and moves with screen in the same snapshot (single GetVideoSize plugin call — see after /state above). ezQuake backend unchanged (renderer.ScreenshotWidth/Height).

#42 — Fair judgement for content-sized elements

DYNAMIC_WIDTH = ['ping'] in tools/qa/invariants.mjs: proportionality and metamorphic judge ping on x/y/h, never width; position drift still fails; every report carries exempt_width so reviewers see the exemption was applied; extending the list requires naming the element in a PR (docs/TESTING.md).

#43 — Demo pause (user journey)

Journey: press Pause next to the volume control → demo freezes (democlock pixels stop); press Resume → it moves again. Type demo_setspeed 0 in the console instead → the button flips to Resume on the next poll, because it renders engine state, never click state.

On a backend that does not report demo.cl_demospeed, the control renders disabled with a reason and logs one warn-level session-log entry (tier-3F case). demo_setspeed is a percent on both engines (0 pauses, 100 restores) — the protocol doc and allowlists say so explicitly, with negative tests for lookalikes and chaining.

Known limitations

  • The classic.* matrix axis has no expectations of its own yet (sbar is engine-drawn, not a plugin element) — follow-up issue filed.
  • Real-run ping width variation is currently pinned static by the master cfg, so the #42 exemption is proven at unit level; a live-variation cell is a follow-up.
  • Pausing freezes demo time, not cl.time: the gameclock keeps ticking while paused (engine behaviour, documented in the spec and tests).
  • Golden screenshots (perceptual diff) remain unblessed — the capture hook exists, blessing is future work.
